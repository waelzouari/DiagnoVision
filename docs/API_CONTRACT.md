# API contract

The canonical, executable schema is FastAPI OpenAPI at `/docs` and `/openapi.json`. All application endpoints use `/api/v1`, JSON unless a multipart upload is documented, and `Cache-Control: no-store` for authenticated responses.

## Session rules

- `POST /auth/login`, `POST /auth/refresh`, and `POST /auth/logout` manage HttpOnly cookies.
- `GET /auth/csrf` returns/sets the double-submit CSRF value used by the Axios client.
- `GET /auth/me` is the session source of truth.
- Mutating requests send `X-CSRF-Token`; cookies use `SameSite=Lax` and `Secure` outside localhost.
- `401` means absent/expired authentication; `403` means CSRF, origin, or resource authorization failure.

## Resources

| Area | Operations |
| --- | --- |
| Patients | `GET/POST /patients`, `GET/PATCH /patients/{id}`, `GET /patients/{id}/timeline`, `GET /patients/{id}/observations` |
| Consultations | create, consent, audio upload, transcribe, extract, draft edit, approve, and retrieve |
| Live stream | `WS /consultations/{id}/stream`; cookie authentication plus Origin validation |
| Analysis | create analysis job, list patient analyses, retrieve, and review immutable versions |
| Documents | patient upload/list, process, and approve extraction |
| Operations | dashboard overview, job status, doctor settings |

## Asynchronous contract

Queued operations respond `202` with `{ "job_id": "uuid", "status": "pending" }`. Job states are `pending`, `processing`, `completed`, `failed`, or `cancelled`. Completed jobs include a resource reference; failures include a safe user-facing reason and never raw source content or a stack trace.

## WebSocket messages

The client sends a JSON start envelope containing a random session ID and selected MIME type, then bounded binary audio fragments with monotonically increasing sequence metadata. The server may emit `partial_transcript`, `final_transcript`, `ack`, and `error` events. The persisted final transcript is authoritative; partial text is editable but reconciled after stop. Compressed browser fragments are treated as one continuous stream rather than assumed independently decodable.

## Uploads

Audio accepts allowed WAV, MP3, M4A, and WebM signatures. Documents accept PDF, JPEG, and PNG, with optional DICOM only when configured. The backend validates declared type, signature, size, authorization, and sanitized names before private storage.

Payload details and enum values are generated by the running OpenAPI schema; clients should regenerate contracts when it changes.
